# MultiUrlManager 1.3.0 开发与验收

基线：`main / c9e69b6`（1.2.0 发布后的文档提交）。方案确认：2026-11-11。开发版本 `1.3.0-SNAPSHOT`，Demo versionCode `9`；未正式发布。

## 已确定范围

- 修复默认升级不递增 revision、现代 JSON 类型静默转换、删除可选业务最后候选后无法重新添加。
- 保留 AAR 空配置的兼容行为，纠正文档与空状态，不把初始化成功当成业务地址已配置。
- JSON 文件导出已提交配置；文件导入先选择环境和合并/替换模式，再预览，确认仅应用草稿，保存后生效。
- 可新增环境；业务键只能来自包内定义或导入前已存在的配置，展示名与固定策略由宿主控制。
- 合并默认保留本机候选、备注、选择与环境名；替换仅修改选定环境候选并保留本机必选约束。
- 输入上限 256 KiB UTF-8、32 环境、1,000 候选；实际页面恢复 Parcel 预算 256 KiB，超限拒绝并保留原数据。
- 不做搜索、二维码、剪贴板导入、云同步、Compose/Flow、独立网络诊断面板或未测量的路由缓存。

## 契约与实现顺序

1. **M1 可靠性**：默认合并改变语义状态时递增 revision，连同默认基线原子保存后才发布；无变化不重复递增。严格解析新配置，旧数组及旧存储仍兼容。保留编辑会话已知业务。
2. **M2 核心交换**：独立导入结果与差异模型；`exportConfiguration`、`inspectImport`、`previewImport` 不改变现有 SaveResult 分支或模型签名。preview 不持久化，不自动切环境。
3. **M3 文件页面**：系统文件选择器、后台读写、模式与环境选择、差异预览；预览过期时重新生成，取消/解析/写入失败不改正式配置。固定模式禁导入，导出仅固定环境。
4. **M4 验收**：保留 1.0.6/1.1.0 覆盖，追加真实 1.2.0 核心/网络 ABI、源码/二进制消费和升级夹具；更新同轮产物契约，不以旧报告替代新候选。

文件格式和操作步骤以[配置交换](../configuration-transfer.md)为准。新公开接口应有 Java/Kotlin 用法和真实 AAR/R8 消费验证，详细 API 见[API 文档](../api.md)。

## 必须验证

- 默认升级、旧草稿冲突、重复刷新幂等、基线更新、失败写保护和固定模式文件隔离。
- 严格类型、重复字段、非法 URL、必选键、未知业务、重复候选、同组多选、长中文内容与超限文件。
- 导出再导入；合并保留未选择组、替换保留约束；新环境、其他环境不变、预览过期。
- 系统文件取消/不可用/读写失败；旋转和恢复；预览确认不落盘；保存冲突与存储失败；Parcel 预算。
- API 24/36 页面、存储及文件交互；1.2.0 → 1.3.0 普通数据保留与固定模式隔离；旧版本既有验收不减少。
- 中英文 README 示例和新交换示例随真实 AAR 编译并经 R8，文档链接/JSON/XML 及工作流脚本检查。

### 本地验收（2026-11-11）

- 实现保持 `1.3.0-SNAPSHOT` / Demo code `9`，沿用原工具链和依赖。最终核心 JVM 45 项、网络 JVM 16 项通过；Python 脚本 56 项通过。Debug/Release、Lint、本地双制品 Maven 及独立 Debug/R8 消费构建通过，14 份完整文档示例参与编译。
- 最终 Release AAR 对真实 1.0.6、1.1.0、1.2.0 核心与 1.2.0 网络 ABI 校验通过；Kotlin/Java 1.1.0、1.2.0 旧二进制及 current 源码消费运行通过。
- 红米本机覆盖页面 34 项、核心 26 项、网络 2 项和 R8 消费 1 项，零跳过。R8 消费额外直接运行 Java 的导出、检查、合并和替换预览调用。页面完整运行首轮 33 项通过，深色主题截图有一个像素相差 1 色值；保持原 APK 和精确断言不变，单项隔离复核通过。保留首轮日志和该不稳定性，仍需云端矩阵验证，不能称作一次完整运行全绿。
- 红米 Android 16 / API 36 使用隔离 Demo 包。系统文件保存器导出 484 字节 JSON 后，核验环境、候选与设备元数据排除；通过系统选择器重新导入，合并预览无差异，取消未应用草稿。
- 三代真实发行库的 Debug/Release 升级共 36 阶段通过，零跳过。包含 1.2.0 普通配置保留、固定模式不读写普通配置、新进程恢复普通选择。1.0.6 的 18 阶段使用与最终本地候选摘要一致的 APK 结果。
- 修正测试夹具：业务选择标题跟随“展示名 · 业务键”；等待弹窗稳定后点击；独立测试 Provider 使用平台 API，避免测试包进程缺少宿主 Kotlin 运行时；旧升级测试精确验证首次归组落盘后 revision 加一及重复刷新文件不变。
- 额外修复弹窗关闭回调与后台预览结果的时序问题：关闭旧窗口只释放该窗口引用，取消才清除输入，避免错误提示后无法重新预览。
- 红米厂商条件单独记录：测试 Provider 被强制停止后，后台自动启动会被安全中心拒绝；正常打开测试包后，5 项真实文件回调通过。文件回调测试直接激活可见且启用的按钮，真实系统文件选择和触摸由前述往返操作覆盖。复制 URL 后的厂商浮层曾接管下一用例触摸并打开浏览器，本机将剪贴板用例放在页面组最后，不修改系统权限或安全开关。
- 原应用 `com.logan.multiurlmanager` 的 files/shared_prefs 与测试前备份逐文件摘要一致。验证创建的下载 JSON 已核验并清理，本机不启动模拟器。
