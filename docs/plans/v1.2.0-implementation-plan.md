# MultiUrlManager 1.2.0 开发与验收

方案执行日期：2026-10-30。基线：`main` / `885898f`，起始工作区干净。当前源码为 `1.2.0` 正式版本候选，尚未发布。

## 目标与范围

在 1.1.0 的快照、草稿、冲突检测、原子保存及迁移之上，提供可选的真实网络路由、宿主显式固定环境模式，以及能区分生效状态和草稿的管理页。保留原制品和模型签名，新增 `multiurlmanager-okhttp` 可选制品。

借鉴 [RetrofitUrlManager](https://github.com/JessYanCoding/RetrofitUrlManager) 的业务路由和路径处理、[EnvironmentSwitcher](https://github.com/CodeXiaoMai/EnvironmentSwitcher) 的展示名与正式环境策略、[Beagle](https://github.com/pandulapeter/beagle) 的可选模块与信息组织，以及 [BaseUrlManager](https://github.com/jenly1314/BaseUrlManager) / [RetrofitHelper](https://github.com/jenly1314/RetrofitHelper) 的职责划分。

## 已确定契约

- 普通模式延续 1.1.0。固定模式只使用指定的内置环境，不读取、迁移或写入普通模式存储；同一进程不得以不同模式重复初始化。
- 固定模式缺键返回 null；缺键时不能用 fallback 引入地址；相同快照保存返回无变化，实际修改使用既有 VALIDATION 失败；刷新不读取磁盘。
- 路由仅处理显式业务标记以及登记的来源 origin / 路径范围。缺映射或来源不符明确失败；未标记请求不改变。
- 每个请求进入 application interceptor 时读取一次快照，固定请求的环境上下文；鉴权按该上下文取得凭据，不能再次读取可能已切换的当前环境。
- 替换完整 Base URL 前缀，保留编码路径、query、method 与 body；不猜测绝对路径的意图。跨目标不能直接携带预附加凭据。
- 业务展示名为独立元数据，不修改已有 data class、Parcelable 和存储格式。页面内显示变更摘要，仍通过现有保存动作提交。
- 配置导入导出、Compose、远程配置、自动故障切换、多进程不在本版范围。
